# ADR-001 — Real executable platform runtime

**Status:** `PROPOSED_FOR_REVIEW` | **Date:** 2026-10-28 | **Decision maker:** to assign at Gate-01

## Context

Historical GPT-only roles cannot provide durable engine contracts, permissions, image QA or proper business actions.

## Proposed decision

Use an audited modular application runtime with separately tested bounded engines; preserve legacy behavior as source contracts.

## Consequences and tradeoffs

Increased engineering work and cost; enables independently verifiable behavior.

## Alternatives still to assess

Consider minimal platform alternatives and vendor capability through a POC; no implementation is claimed by this decision document. No single provider is mandatory without benchmark evidence.

## Affected contracts

`ABC-F05,ENG-01`; update relevant schemas, engine tests, migration map and risk register before marking this ADR accepted.

## Verification and exit

Demonstrate contract test(s), integration flow and negative/failure cases appropriate to this decision. Capture code SHA, test execution result, human reviewer and linked issue/PR; status remains PROPOSED until review.

## WP-000-02 — Detailed platform-vs-legacy disposition (2026-10-29)
**Status remains `PROPOSED_FOR_REVIEW`.** Historical DOC-000/001/005/006/016/900 authorize GPT-only V1 and do NOT describe an operational platform. Current user target requires an independent salon application. **Option A:** keep GPT-only: fails backend auth, versioned image QA, persistence, real business operations. **Option B:** isolated microservice per ENG: unnecessary early operational complexity. **Preferred Option C:** modular domain application with versioned contracts, separate CV/GPU workers, durable orchestrator. Do not conflate 19 logical engines with 19 deployed services.
**Migration:** MIG-01/02/16; preserve AG-01..10 as historical semantics (see `../phase-00/wp-000-02/LEGACY_AGENT_TO_ENGINE_MAP.md`); require API schemas, data authority and integration tests in Phase 02/04. **Failure-mode controls:** non-bypassable policy, trace/retry/idempotency, no GPT-generated success without backend verification. **Approval:** Product + Architecture Authority with source exception disposition; no runtime signoff claimed.
