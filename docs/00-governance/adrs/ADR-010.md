# ADR-010 — Tenant security and QA from foundation

**Status:** `PROPOSED_FOR_REVIEW` | **Date:** 2026-10-28 | **Decision maker:** to assign at Gate-01

## Context

Shared display/private images/many salons create privacy and safety risks.

## Proposed decision

Backend permissions, scoped consent, asset controls, continuous eval from Phase 04.

## Consequences and tradeoffs

Some early overhead; reduces systemic rework.

## Alternatives still to assess

Consider minimal platform alternatives and vendor capability through a POC; no implementation is claimed by this decision document. No single provider is mandatory without benchmark evidence.

## Affected contracts

`PRD-002,PRD-019`; update relevant schemas, engine tests, migration map and risk register before marking this ADR accepted.

## Verification and exit

Demonstrate contract test(s), integration flow and negative/failure cases appropriate to this decision. Capture code SHA, test execution result, human reviewer and linked issue/PR; status remains PROPOSED until review.

## WP-000-02 — Tenant, shared-screen and continuous QA controls (2026-10-29)
**Status remains `PROPOSED_FOR_REVIEW`.** Tenant/branch identity server-derived from authenticated membership; all DB rows, search results, asset URLs, queues, audit and analytics queries are scoped and tested for no cross-tenant leakage. Backend authorization and asset access checks are mandatory; frontend hiding never suffices. Consent and image retention/deletion by jurisdiction and purpose require approved privacy policy before launch. Shared display separates default client-visible UI from privileged specialist/admin data with explicit identity checks.
**Security review:** cross-tenant ID guessing, mis-scoped asset links, unauthorized screenshot/export, prompt injection against tool actions, stale approvals, log PII leakage, business-action permission escalation. **Testing:** negative tenant/role tests, image access and deletion, consent withdrawal, E2E shared-view privacy, audit evidence; QA harness starts in foundation Phase 04. **Alternative:** deferred policy/security and prompt-only guard rejected. **Approval:** Security/Privacy + QA Authority; legal-specific compliance not asserted absent review.
